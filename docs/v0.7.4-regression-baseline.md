## 比較セットの固定方法

既存`test/epubs`から下表のファイルをタグの内容で取り出す。生成スクリプトを再実行したファイルに置き換えない。ZIPコンテナの差でBookIdが変わる場合があるため、比較元と比較先でEPUB全体のSHA256を一致させる。

付属の`baseline-manifest.json`に、固定コミット、SDK、公開アセットのSHA256、fixtureのGit blob・SHA256・ZIP CRC/XML検査結果・spine順を記録する。fixtureはSDの`/books/yomuka-v073-baseline/`へコピーする。ファームウェア参照物は`reference-firmware/`に分離してあり、SDへフォルダーごとコピーしない。

## 実施結果

実施日：2026-09-11〜12。実施者名、個体識別名、SDカードのメーカー・形式、各試験で書き込んだfirmware SHA256は未記録のため、後から推定して補わない。端末はX4を主対象とし、R16はX3でも確認した。

共通条件は次のとおり。

- テーマ：Lyra。画面方向：縦向きを基準。
- 縦書き：NotoSerifJP、サイズ中、行間0.95、段落標準、余白標準、字間標準、ルビON、一行目インデントON、ハイフネーションOFF。
- 横書き：NotoSansJP、サイズ中、行間0.95、左揃え、段落標準、余白標準、ルビON、一行目インデントON、ハイフネーションOFF。
- EPUBスタイル：書籍優先。画像：ON。全体更新：30ページごと。
- 前面／側面ボタン：通常割り当て。自動sleep：30分。電源長押し設定は未記録。
- 書籍別設定：なし。

| ID | 結果 | 記録 |
|---|---|---|
| R01〜R08 | 合格 | X4で確認。R07はZenMaruGothicへの変更時に一度メモリエラーが出たが、再起動後は再現しなかった。診断保存後に本文へ戻ってもホームへ移動しないことを確認。 |
| R09 | 合格 | 元のfixtureでは生成が速く取消操作が間に合わなかったため、より大きい別ファイルで生成の取消と再開を確認。 |
| R10 | 初回不合格、修正後合格 | 横向き右上で読書中のページ送り／戻しが縦向きと逆になり、読書メニューでは横向き時に側面ボタンが効かなかった。横向き右上ではメニューのボタン表示も重なった。向きごとの入力と表示を修正し、X4で再確認した。 |
| R11〜R15 | 合格 | X4で位置・しおり・完読表示、USB有無を含むsleep／復帰、反復復帰、sleep中のSD抜き差しを確認。R13のUSB有りはPCへ接続した状態で実施。 |
| R16 | 合格 | X3でRTCを含む対象動作を確認。 |

R07の一過性メモリエラーとは別に、全冊キャッシュ生成でIssue #37相当のX4低メモリ経路とIssue #36のX3終盤クラッシュを追加調査した。X4は全26冊、X3は問題の大きいセクション163・175・187を含めて完走し、低メモリ時に安全に中断またはSDフォントキャッシュを回収する修正を実機で確認した。

R10の修正後にR11〜R16を確認しているため、これらは公開v0.7.3バイナリの未変更状態を示す記録ではなく、v0.7.4開発版の回帰確認でもある。公開v0.7.3との厳密な画面比較が必要になった場合は、固定済みの公開バイナリとfixtureを使って別試験として残す。

## 証跡

- 「設定」→「本体」→「診断」、またはEPUB読書中の「決定」→「ツール」→「診断」から開く。診断画面の保存（決定キー）で保存し、表示された保存先を記録する。保存場所は`/.crosspoint/diagnostics/`。
- POWER＋DOWNで保存したBMPは`/screenshots/`。フレームバッファの証跡であり、残像・濃度・sleep中の画質は端末写真も必須。
- 起動直後、R08再読込後、R14終了後に同じ経路で診断を保存する。診断画面を開くこと自体によるメモリ変化もあるので条件を揃える。
- v0.7.3診断には版、機種、SD容量、free_heap、max_alloc_heap、min_free_heap、書籍キャッシュ状態、spine/page、字体等がある。一方、firmware SHA、SDK SHA、全設定、X4 controller、wake reasonは全て揃うわけではない。手動記録や必要時のシリアルログで補う。読書画面を離れてactive_bookがfalseになった場合は本文画面と位置を手動記録する。
- 証跡名：`X4-A_baseline_R05_chapter0_portrait.bmp`など。比較先は`candidate`とし、基準画像を上書きしない。
- クラッシュ時は`/crash_report.txt`と直前の診断・操作を保存。個人の書籍名等がログに含まれる可能性があるため、公開前に内容を確認する。

## 判定と次工程

準備完了と実機基準採取完了を別々に記録する。順序1の準備はfixtureとバイナリの固定・チェック表の用意で完了。2026-09-12時点でR01〜R15をX4、R16をX3で確認し、ユーザー報告による実施結果を本書へ固定した。未記録の個体情報、firmware SHA256、SD情報、画面写真は推定で補完せず、将来厳密な公開版比較が必要になったときの追加証跡とする。

不具合、表示差、heap減少があれば原因・影響を評価するまで合格にしない。heapは単発の差だけで失敗とせず、同じ手順で再現する減少・連続領域不足・割当失敗を確認する。SDK更新後のX4確認は、この基準と対で行う。

順序2の独立したソース整理は準備後に開始できるが、SDK更新の受入れやv0.7.4の安定性判定には実機証跡が必要。X4 V2/Proはビルド／Simulator確認までで、実機合格欄を埋めない。
