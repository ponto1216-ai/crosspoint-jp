# CrossPoint Yomuka ロードマップ

更新日: 2026-09-10。基準: v0.7.3。

将来の候補を整理した文書であり、実装やリリース時期を保証するものではありません。[使い方](manual-ja.md)と[開発者ガイド](contributing/README.md)は別ページです。

## 実装済みの土台

- FreeInk SDKによるX3/X4共通ファーム、X3の表示コントローラ判別。
- 日本語の縦書き・横書き、ルビ、太字、SDフォントと端末ダウンロード。
- 全体と書籍別の読書設定、読書設定プロファイル、診断レポート、分類した読書中メニュー。
- 書籍識別を使う読書位置・しおり・設定の引き継ぎ、読書履歴と読書メーター。
- EPUBの画像最大寸法、SVGで包まれた画像・SVG表紙、圏点・下線・取り消し線、PNG/JPEG共通のPXCキャッシュ。
- 多数の本・フォルダで一覧キャッシュが積み重なる問題への対策。

これは各機能の存在の整理です。実書籍の全不具合や過去のIssueが解決済みという意味ではありません。版ごとの変更は[リリース](https://github.com/ponto1216-ai/crosspoint-jp/releases)を参照してください。

## 旧計画から引き継ぐ項目

読書設定プロファイル・書籍別設定・診断・メニュー分類は現行機能として扱います。「本を修復する」という一括操作、互換性チェック、画像失敗理由の統一的な観測は、既存の個別キャッシュ操作とは区別して後続候補に残します。

特定Issueの原因確定、X3のUSB診断経路、長押し章送り境界、UI文字範囲、Noto Serif JPのウェイト・太字検証は、旧計画だけを根拠に完了に変えません。[旧計画原文](archive/planning/roadmap-before-v0.7.4.md)と実装・検証記録を照合します。

## 継続する原則

- 読書位置・しおり・設定・インストール済みフォントを不必要に失わない。
- レイアウトと保存形式の変更には対象キャッシュの再生成とX3/X4の確認を伴わせる。
- 書籍本文や認証情報を共有の前提にせず、診断と再現手順で調査する。
- 無関係な作業をリリースへ混ぜず、Flash/RAMの余裕は計測して判断する。

## 後続候補: 派生プロジェクトからの選択的な取り込み

今後は、他の CrossPoint 派生プロジェクトや上流の成熟した改善を参考にする。ただし、履歴をまとめて取り込むのではなく、YomukaのX3/X4共通構成、日本語EPUB、SDフォント、キャッシュ安全性、現在の配布方式に適合する変更だけを選ぶ。

### Bluetooth HID ページターナー

Bluetoothのキーボード型ページターナーを、独立した機能候補とする。スマートフォン連携や任意のBluetooth機器を広く扱うのではなく、読書中のページ送りに必要なBLE HIDリモコンへ範囲を限定する。

- ペアリング、再接続、接続状態を設定画面で安全に操作できるようにする。
- Page Forward／Page Backを中心に、実際に受信したキーを任意の論理ボタンへ割り当てる。定番ページターナー用の初期設定は、実機確認後に追加する。
- 本体ボタンとBLE入力は同じ論理入力へ統合し、縦書きの方向、画面回転、長押し章送り、読書メニューを一貫して扱う。
- BLE操作を自動スリープの活動として扱い、接続・切断・再接続の状態を診断レポートへ残す。
- Wi-Fi利用時、EPUBキャッシュ生成時、低heap時はBLEを安全に停止・再開できるようにする。読み込み失敗を隠して再試行するのではなく、停止・再開・失敗理由を記録する。
- X3/X4で、通常読書、縦書き、画像付きEPUB、スリープ復帰、Wi-Fi利用後、長時間接続、低heap時のキャッシュ生成を確認する。

BLEはNimBLEとHIDホストのためにFlash/RAMを消費し、EPUBの連続確保と競合し得る。採用前に配布用ビルドの容量、通常読書・画像ページ・キャッシュ生成中のfree heap／最大連続確保量、スリープ時の消費電力を測定し、必要ならBLEなしの通常ビルドを維持する。

### 候補となる改善領域

- **更新・復旧の信頼性**: 安定版／試験版の更新経路、更新失敗時の状態表示、起動不能な新ファームからの安全な復旧。OTAチャネルや自動ロールバックは、現在の配布方式とパーティション構成を個別に検証した後に扱う。
- **読書操作とホーム**: 長押し、読書終了、進捗復帰、一覧の書誌情報表示、同名書籍を区別しやすい表示など、読書位置を失わない改善。
- **フォントとUI運用**: フォントの導入状態・削除・不足文字の表示、UI文字範囲の検証、設定項目の整理。YomukaのSDフォント配布方式を維持できるものに限る。
- **パフォーマンスと省電力**: ホームの表紙キャッシュ、更新頻度、スリープ・復帰、画像ページ後の同期。X3/X4の残像、操作待ち、消費電力を実機で比較して採否を決める。
- **テストと配布の品質**: 更新判定、バージョン比較、キャッシュ検証、フォント範囲をホストテスト・CIで検証し、再現可能なリリース手順へ取り込む。

### 取り込みの手順

1. 元のIssue、コミット、実機で解決している症状を確認する。
2. Yomukaの現行実装との差分と、X3/X4、Flash/RAM、キャッシュ、設定、配布方式への影響を記録する。
3. 機能単位の独立ブランチで実装・検証する。SDK更新、OTA刷新、キャッシュ形式変更を小さな操作改善と同じ変更へ混ぜない。
4. X3/X4で対象の利用シナリオを確認し、既存の読書位置・キャッシュ・SDフォントが維持されることを確認する。
5. 採用した機能と、意図的に採用しなかった機能・理由をリリースノートとロードマップへ記録する。

### 当面は保留するもの

- 特定フォーク固有の認証、クラウド連携、プラグイン基盤、端末専用ハードウェア機能。
- 既存ユーザーの更新を危険にする一括マージ、パーティション変更、未検証のOTA自動化。
- 日本語表示、画像ページ、X3/X4の実機回帰を経ていない表示SDK更新。

## 中期: EPUB互換性と画像ページ

### EPUB互換性チェック

書籍を開く前または初回解析時に、Yomukaで問題化しやすい構造を検出して警告する。

- 大きなXHTML、過剰なCSS、異常に多い章、巨大画像、未対応・壊れた参照、埋め込みフォント、画像形式を記録する。
- 「読めない」と断定せず、想定される影響と診断レポートの保存方法を案内する。
- 自動変換や内容改変は、互換性チェックと分離して検討する。

### 画像レンダラーの整理

- JPEG、PNG、GIF、SVG由来画像の失敗経路とメモリ使用量を統一的に観測する。
- 画像ページの前後で必要なフル更新を選び、残像と操作待ちのバランスを実機で評価する。
- 漫画・挿絵向けの縮小、ディザリング、画像優先モードは、基礎的なメモリ安全性を確立してから検討する。

## 継続的な品質項目

- 日本語の縦書き、ルビ、太字、半角／全角数字、句読点・鍵括弧、英字、画像前後をNoto系とBIZ UD系フォントで確認する。
- X3/X4のページ送り、フル更新、スリープ、復帰、SDフォント、フォントダウンロード、Wi-Fiを使う機能を確認する。
- 変更がキャッシュの見た目や保存形式に影響する場合、旧キャッシュを安全に無効化し、再生成・再起動・読書位置復元まで確認する。
- リリース前に、対象ビルド、差分検査、CI、配布物、更新手順、既知の制限を確認する。

## 明確に保留するもの

- OTAチャネル、自動ロールバック、SDファーム更新経路の大規模刷新。現在の配布・更新方式との整合を独立して検証してから扱う。
- パネル波形、電圧、表示コントローラを直接変更する常用設定。
- EPUB本文や画像を外部へ送る前提の診断・互換性機能。
- 実機でのメモリ安全性・キャッシュ安全性が確認されていない大規模なEPUB自動修復。
