# CrossPoint Yomuka ロードマップ（v0.7.1 以降）

更新日: 2026-09-04
基準: `main` / `yomuka-v0.7.1`

CrossPoint Yomuka は CrossPoint Reader / CrossPoint JP を基にした非公式のコミュニティフォークです。本書は将来の方向性を示すものであり、各項目の実装・リリースを保証するものではありません。

## 現在地

v0.7.1 までに、FreeInk SDK を使う X3/X4 共通ファーム、UC8279 を含む X3 パネル判別、日本語SDフォントの導入・安全なダウンロード再開、EPUBの縦書き・ルビ・太字・画像・キャッシュ安定化を整備した。書籍固有データはソース指紋を基準に保存し、EPUBの移動・改名・更新後にも読書位置、しおり、読書設定、履歴を引き継ぐ。

現在の最優先は、機能を大きく増やすことではなく、実際の書籍で起きた問題を安全に切り分け、読書環境を再現・復元しやすくすることである。Issue #26 の画像ページでのメモリエラーは、診断テスト版からの報告を待って原因を確定する。

縦書きはUAX #50を文字方向の基準とし、フォントごとの見た目の差とUnicode上の方向規則を分けて検証する。SDカードフォントは、実際の元フォントに字形がある文字だけを追加し、空の字形を配布しない。

## 継続する原則

- 読書位置、しおり、既存キャッシュ、インストール済みフォントを不必要に失わない。
- EPUBのレイアウト、キャッシュ、フォント、画像、表示SDKの変更は、ビルド成功だけで完了とせず、X3とX4の実機で確認する。
- 書籍本文、画像、Wi-Fi認証情報を診断レポートや共有用設定へ含めない。
- レイアウトのシリアライズ結果が変わる場合は、キャッシュ形式を更新して対象キャッシュを安全に再生成する。
- `serial.txt`、`font_src/`、ワークスペース設定、SDKの未関係な作業はリリースへ混ぜない。
- Flash/RAMの余裕は実測を確認しながら、読書品質・UI可読性・診断能力へ優先的に使う。

## 直近: v0.6.1 — 実書籍の安定性

### 目標

Issue #26 を根拠に、画像ページを含むEPUBで発生するメモリエラーを再現・修正し、失敗時にも原因を追跡できる状態にする。

### 候補

- Issue #26 のレポートに含まれる `[SCT]`、`[ERS]`、`[IMG]` を基に、画像デコード、キャッシュ生成、レンダリングのどこで失敗しているかを確定する。
- 必要最小限の修正を行い、問題の書籍を別名コピーして検証し、既存の読書位置とキャッシュを保護する。
- X3が満充電時にUSB Serialを有効化できない上流修正を取り込み、書き込みと診断ログ取得の経路を安定化する。
- 章のない方向へ長押し章送りをした場合に、先頭・末尾へ誤って移動しないよう境界を保護する。

### 完了条件

- X3で対象ページを開ける、または安全に失敗して診断レポートへ原因を残せる。
- X3/X4で通常EPUB、画像付きEPUB、縦書き、ルビ、SDフォント、ページ送り、スリープ復帰を確認する。
- 既存の書籍キャッシュと読書位置が意図せず失われない。

## 近い将来: v0.6.2 — 設定・診断・UIの運用性

### 読書設定プロファイル

端末間の検証条件合わせと、試験後の復元を目的に、読書に関係する設定だけをJSONプロファイルとしてSDカードへ保存・読込できるようにする。

- 横書き／縦書き別のフォント、文字サイズ、行間、字間、余白、段落、ルビ設定。
- 書籍スタイル、表示方向、画像表示、更新頻度、長押し章送りなどの読書設定。
- Wi-Fi、ボタン割当、言語、スリープ画面、読書位置、キャッシュ、認証情報は含めない。
- 読込前に自動バックアップを作成し、値を検証してから確認付きで適用する。
- 未導入のSDフォントは理由を表示し、安全なフォールバックを使う。

### 診断レポート v2 と開発者・診断モード

一般利用者にも安全な読み取り専用の診断画面を維持し、詳細が必要な時だけ開発者モードを有効化する。

- 現在の書籍の形式、サイズ、ソース指紋、キャッシュ状態、spine／章／ページ、縦横、使用フォント、読書プロファイルを記録する。
- free heap、最大連続確保量、最小heap、X3の表示コントローラ、直近のエラーとログを記録する。
- 画像デコード、EPUB解析、キャッシュ生成の失敗理由を、本文や画像を含めずにレポートへ残す。
- 開発者モードでは処理時間、詳細キャッシュ状態、限定したログを追加する。LUT・電圧・パネル種別の強制指定や任意削除は通常機能に入れない。
- レポートはSDカードへ日時付きテキストとして保存し、Issueへ添付できるようにする。

### 設定画面とUI文字範囲

- 設定の4分類（表示／読書／操作／システム）を維持し、読書タブを「横書き」「縦書き」「読書プロファイル」「フォント管理」「ステータスバー」の順に整理する。
- UIフォントは翻訳文字列だけでなく、設定名、診断メッセージ、書籍名・作者名で頻出する漢字・記号を対象に範囲を拡張する。
- UI文字が不足した場合にビルドで検出できるチェックを維持・拡張する。Unicode全域を無差別に埋め込まず、Flash使用量と実機の可読性を測定して段階的に増やす。

### Noto Serif JP の通常・太字表示

従来の読書表示に合わせ、Noto Serif JPの通常スタイルをRegularではなくMedium（可変フォントの `wght: 500`）として再生成する。太字はBold（`wght: 700`）を別スタイルとして保持する。

- 配布用 `.cpfont` にRegular相当のstyle 0とBoldのstyle 1が含まれることを生成後に検査する。
- 実機で `font-weight: bold`／`700`、`<b>`、`<strong>` の日本語・英数字・句読点を通常文と比較し、Noto Serif JPの太字が視認できることを確認する。
- フォント差し替え後も、既存書籍の読書位置・しおりは保持する。太字の見え方を再確認する書籍だけ、必要に応じて対象書籍のキャッシュを再生成する。

### 読書メニューの整理

読書中にすぐ使う操作と、恒久的な設定・復旧操作を分け、長い平坦なメニューを避ける。

- 最上位は「読書位置」（章、進捗、しおり）、「表示・組版」（画面回転、行間、行頭、ルビ、画像表示、自動ページ送り）、「書籍管理」（キャッシュ生成の再開、書籍情報、診断・スクリーンショット）、「詳細設定」、「ホーム」に整理する。
- すぐ値を変える項目は、選択中に現在値を表示し、決定で編集開始、左右で変更、決定または戻るで編集終了という規則にそろえる。読書画面でのページ送りと、メニュー内の移動に使うボタンの役割は、画面上のヒントと実機確認を伴って整理する。
- しおり、脚注、キャッシュ生成などは、利用可能な場合だけ表示する。実装だけ残っていて画面から到達できない操作は、利用者向け導線として復活させるか、未提供としてコードを整理するかを決める。
- キャッシュ削除や設定初期化などの破壊的操作は最上位へ置かず、「書籍管理」または診断から確認付きで実行する。読書位置・しおり・他書籍のキャッシュを失う範囲を操作前に明示する。

### 完了条件

- X3/X4で、設定保存→任意変更→読込復元、未導入SDフォントの読込、破損プロファイル拒否を確認する。
- 通常診断と詳細診断の両方で、書籍本文や認証情報を含まないレポートを保存できる。
- 長い日本語ラベル、頻出記号、書籍名で文字欠落・重なり・切れがないことを実機で確認する。
- X3/X4で、横書き・縦書き・画像付きEPUBについて、読書画面からメニューを開き、章移動、しおり、進捗移動、編集操作、キャッシュ再開、詳細設定から読書画面への復帰を確認する。

## 次段階: v0.6.3 — 書籍ごとの読書環境

### 書籍別設定

本ごとに最適な読み方を保存し、グローバル設定を変えずに自動復元する。

- この本だけの縦横、フォント、文字サイズ、行間、余白、ルビ、書籍スタイル、画像表示を設定する。
- 「この本だけの設定を使う」「グローバル設定に戻す」「この本の設定を初期化」を本のメニューへ置く。
- 設定は書籍パスだけでなく、既存のソース指紋と結び付ける。同じ場所に別のEPUBを置いても、古い設定を誤適用しない。
- 描画に影響する設定の指紋をキャッシュ検証へ加える。設定変更時はその本だけを無効化・再生成し、他書籍には影響させない。

### 本を修復する

書籍別設定と診断を土台に、問題報告時の初動を簡潔にする。

- 読書位置としおりを維持したまま、対象書籍のキャッシュ検査・削除・再生成を行う。
- 書籍別設定だけを初期化できるようにする。
- EPUB再解析や画像キャッシュ再生成は、対象・時間・失われないデータを確認してから実行する。

## v0.7.0 以降: 派生プロジェクトからの選択的な取り込み

v0.7.0 以降は、他の CrossPoint 派生プロジェクトや上流の成熟した改善を参考にする。ただし、履歴をまとめて取り込むのではなく、YomukaのX3/X4共通構成、日本語EPUB、SDフォント、キャッシュ安全性、現在の配布方式に適合する変更だけを選ぶ。

### Bluetooth HID ページターナー

Bluetoothのキーボード型ページターナーを、v0.7系の有力な独立機能候補とする。スマートフォン連携や任意のBluetooth機器を広く扱うのではなく、読書中のページ送りに必要なBLE HIDリモコンへ範囲を限定する。

- ペアリング、再接続、接続状態を設定画面で安全に操作できるようにする。
- Page Forward／Page Backを中心に、実際に受信したキーを任意の論理ボタンへ割り当てる。定番ページターナー用の初期設定は、実機確認後に追加する。
- 本体ボタンとBLE入力は同じ論理入力へ統合し、縦書きの方向、画面回転、長押し章送り、読書メニューを一貫して扱う。
- BLE操作を自動スリープの活動として扱い、接続・切断・再接続の状態を診断レポートへ残す。
- Wi-Fi利用時、EPUBキャッシュ生成時、低heap時はBLEを安全に停止・再開できるようにする。読み込み失敗を隠して再試行するのではなく、停止・再開・失敗理由を記録する。
- X3/X4で、通常読書、縦書き、画像付きEPUB、スリープ復帰、Wi-Fi利用後、長時間接続、低heap時のキャッシュ生成を確認する。

BLEはNimBLEとHIDホストのためにFlash/RAMを消費し、EPUBの連続確保と競合し得る。採用前に配布用ビルドの容量、通常読書・画像ページ・キャッシュ生成中のfree heap／最大連続確保量、スリープ時の消費電力を測定し、必要ならBLEなしの通常ビルドを維持する。

### 候補となる改善領域

- **更新・復旧の信頼性**: 安定版／試験版の更新経路、更新失敗時の状態表示、起動不能な新ファームからの安全な復旧。OTAチャネルや自動ロールバックは、現在の配布方式とパーティション構成を個別に検証した後に扱う。
- **読書操作とホーム**: 長押し、読書終了、進捗復帰、一覧の書誌情報表示、同名書籍を区別しやすい表示など、読書位置を失わない改善。
- **フォントとUI運用**: フォントの導入状態・削除・不足文字の表示、UI文字範囲の検証、設定項目の整理。YomukaのSDフォント配布方式を維持できるものに限る。
- **パフォーマンスと省電力**: ホームの表紙キャッシュ、更新頻度、スリープ・復帰、画像ページ後の同期。X3/X4の残像、操作待ち、消費電力を実機で比較して採否を決める。
- **テストと配布の品質**: 更新判定、バージョン比較、キャッシュ検証、フォント範囲をホストテスト・CIで検証し、再現可能なリリース手順へ取り込む。

### 取り込みの手順

1. 元のIssue、コミット、実機で解決している症状を確認する。
2. Yomukaの現行実装との差分と、X3/X4、Flash/RAM、キャッシュ、設定、配布方式への影響を記録する。
3. 機能単位の独立ブランチで実装・検証する。SDK更新、OTA刷新、キャッシュ形式変更を小さな操作改善と同じ変更へ混ぜない。
4. X3/X4で対象の利用シナリオを確認し、既存の読書位置・キャッシュ・SDフォントが維持されることを確認する。
5. 採用した機能と、意図的に採用しなかった機能・理由をリリースノートとロードマップへ記録する。

### 当面は保留するもの

- 特定フォーク固有の認証、クラウド連携、プラグイン基盤、端末専用ハードウェア機能。
- 既存ユーザーの更新を危険にする一括マージ、パーティション変更、未検証のOTA自動化。
- 日本語表示、画像ページ、X3/X4の実機回帰を経ていない表示SDK更新。

## 中期: EPUB互換性と画像ページ

### EPUB互換性チェック

書籍を開く前または初回解析時に、Yomukaで問題化しやすい構造を検出して警告する。

- 大きなXHTML、過剰なCSS、異常に多い章、巨大画像、未対応・壊れた参照、埋め込みフォント、画像形式を記録する。
- 「読めない」と断定せず、想定される影響と診断レポートの保存方法を案内する。
- 自動変換や内容改変は、互換性チェックと分離して検討する。

### 画像レンダラーの整理

- JPEG、PNG、GIF、SVG由来画像の失敗経路とメモリ使用量を統一的に観測する。
- 画像ページの前後で必要なフル更新を選び、残像と操作待ちのバランスを実機で評価する。
- 漫画・挿絵向けの縮小、ディザリング、画像優先モードは、基礎的なメモリ安全性を確立してから検討する。

## 継続的な品質項目

- 日本語の縦書き、ルビ、太字、半角／全角数字、句読点・鍵括弧、英字、画像前後をNoto系とBIZ UD系フォントで確認する。
- X3/X4のページ送り、フル更新、スリープ、復帰、SDフォント、フォントダウンロード、Wi-Fiを使う機能を確認する。
- 変更がキャッシュの見た目や保存形式に影響する場合、旧キャッシュを安全に無効化し、再生成・再起動・読書位置復元まで確認する。
- リリース前に、対象ビルド、差分検査、CI、配布物、更新手順、既知の制限を確認する。

## 明確に保留するもの

- OTAチャネル、自動ロールバック、SDファーム更新経路の大規模刷新。現在の配布・更新方式との整合を独立して検証してから扱う。
- パネル波形、電圧、表示コントローラを直接変更する常用設定。
- EPUB本文や画像を外部へ送る前提の診断・互換性機能。
- 実機でのメモリ安全性・キャッシュ安全性が確認されていない大規模なEPUB自動修復。
