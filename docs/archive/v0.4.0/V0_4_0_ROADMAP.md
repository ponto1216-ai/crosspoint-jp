# CrossPoint Yomuka v0.4.0 ロードマップ

> 過去の設計・計画または記録です。現在の仕様や実装完了を示すものではありません。
> 保存元: `docs/V0_4_0_ROADMAP.md`（v0.7.3時点）。


## 目標

v0.4.0 は大きな機能拡張よりも、EPUB読書の安定性を優先する。
直近の縦書き・SDフォント対応を実機で繰り返し確認できる形にし、
次の不具合報告で安全に原因を切り分けられる状態を目指す。

## 対象範囲

### 1. 読書レイアウトの基準を固定する

**完了**。確認用EPUBでBIZUDおよびNoto系SDフォントの縦書き・横書きを確認し、
半角約物・単独濁点/半濁点の調整を反映した。

- 縦書きの半角約物と単独濁点・半濁点の修正を、確認用EPUBで継続的に確認する。
- BIZUD とNoto系SDフォントで、縦書き・横書きを確認する。
- レイアウト形式が変わるたびに読書キャッシュを再生成し、しおりと読書進捗が維持されることを確認する。

### 2. キャッシュとReaderの安定性を確認する

**完了**。完了マーカー無効化、設定不一致の診断、小さなEPUBの初回確認省略を実装し、
キャッシュ生成の中断/再開と、書籍単位のキャッシュ削除後もしおり・読書進捗が
維持されることを実機で確認した。

- 通常読書、全読書キャッシュ生成、中断、再開、書籍単位のキャッシュ削除、ファイル転送後の再読込を確認する。
- 全読書キャッシュ完了マーカーは、すべてのSectionと画像の生成成功後にだけ有効とする。
- レイアウトのシリアライズ結果が変わる修正では、キャッシュ形式のバージョン更新を必須とする。

### 3. Issue #18 の証拠を採取できるようにする

**診断準備完了**。暫定対策と診断ログの動作を確認済み。元の症状を捕捉するまで、
Issue #18は `needs reproduction` として維持する。

- 本番ファームウェアへ冗長な診断ログは追加しない。
- debug専用ビルドでは、ファイル転送完了、Reader開始、縦字形データ読込結果、空きヒープ、最大連続確保領域を記録する。
- 元の症状をこの情報とともに捕捉するまで、Issue #18は `needs reproduction` として維持する。半角約物修正は有効な暫定対策だが、元報告の根本原因の証明ではない。

### 4. 安全な開発者向け診断を追加する

**完了**。X3/X4の両方で、診断画面とSDカードへの診断レポート保存を確認した。

- 本体情報、メモリ、SDカード、キャッシュ、直近ログを読み取り専用で確認できるようにする。
- 日時付き診断レポートをSDカードへ保存できるようにする。
- パネル波形・電圧・任意ファイル削除など、破壊的または危険な操作は通常設定へ追加しない。

## v0.4.0 の対象外

- 現行SDKが必須修正を妨げると確認されない限り、freeink-sdk移行は行わない。移行する場合はX3/X4で独立して検証する。
- WebUIの大規模な再設計や、破壊的なファイル管理機能。
- 実測に基づかない表示波形の実験。
