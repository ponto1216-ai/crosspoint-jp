# CrossPoint Yomuka v0.4.0 実機確認表

> 過去の設計・計画または記録です。現在の仕様や実装完了を示すものではありません。
> 保存元: `docs/V0_4_0_DEVICE_VERIFICATION.md`（v0.7.3時点）。


この表は実機で使用する。ローカルビルドの成功だけで、読書表示の確認を省略しない。

## 使用するテストデータ

| データ | 確認目的 |
| --- | --- |
| `test/epubs/yomuka_vertical_punctuation_check.epub` | 縦書き約物、半角カナ、単独濁点・半濁点 |
| 通常の日本語EPUB | 横書き・縦書き読書、進捗、しおり |
| 画像付きEPUB | インライン画像と画像ページ表示 |
| 長いEPUB | Sectionの遅延生成と全読書キャッシュ生成 |
| TXTおよびXTC/XTCH | EPUB以外の回帰確認 |

## 必須確認マトリクス

縦書き約物確認EPUBを、次の両方のフォントで開く。

| フォント | 横書き | 縦書き | キャッシュ生成後の再読込 |
| --- | --- | --- | --- |
| BIZUD | 合格/不合格 | 合格/不合格 | 合格/不合格 |
| Noto系SDフォント | 合格/不合格 | 合格/不合格 | 合格/不合格 |

縦書きでは `。「」ー`、`｢｣`、`｡､`、`･`、`ｰ`、半角カナ、単独の `ﾞ`・`ﾟ` を確認する。
半角中点は半角字形を保ったまま、セル内で視覚的に中央に見えること。

## キャッシュと転送の確認

**確認済み**：キャッシュ生成の中断/再開、および書籍単位のキャッシュ削除後の
しおり・読書進捗保持を実機で確認した。

初回のキャッシュ生成確認を表示した後は、生成を中断しても再表示しない。Readerメニューの
「残りの読書キャッシュを生成」から、生成済みSectionを再利用して再開する。EPUB本体または
レイアウト設定の変更でキャッシュが無効になった場合は、次回の初回確認を再表示する。

1. 書籍単位の読書キャッシュがない状態でEPUBを開く。
2. 全読書キャッシュを生成し、Readerを閉じて同じ位置を再度開く。
3. 生成を中断し、再開して完了することを確認する。
4. 書籍単位のキャッシュだけを削除し、書籍ファイル・しおり・該当する読書進捗を保ったまま再生成できることを確認する。
5. EPUBを転送し、WebUIを一度使用した後、確認用EPUBを再度開く。

## Issue #18 が再発した場合

縦書き約物の表示がおかしくなった場合、すぐに再起動しない。画面、EPUB名、ページまたはSection、フォント、書字方向、直前の操作、シリアルログを保存する。可能なら確認用EPUBと別の縦書きEPUBでも再現を確認する。次の試行ではdebugファームウェアを使用し、診断レポートとシリアルログをIssue #18へ添付する。

debugファームウェアでは、`I18D` タグで `http-upload-complete`、`ws-upload-complete`、`reader-enter`、`vert-load-success` または `vert-load-skipped` が出力される。各行の `free`、`maxAlloc`、`minFree` を記録する。
